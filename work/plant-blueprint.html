How the model works, and its limits

What is data and what is model. Three things come from public data: the chance a plant has an RMP release in a year, how release records split by where the release came from and what happened, and the share of OSHA 300A filings that fail a plausibility screen. Everything else is a model parameter that I chose: unit layout, nominal readings, noise, alarm limits, incident duration, and the simulated operator's response times. None of those parameters is a measurement of any plant.

Incident clock. Each seed draws two independent streams. The release stream is a Poisson process whose yearly probability is the chosen rate_pct (for example, a plant in the selected inventory band has that share of plant-years with a release). The yearly probability p is converted to an hourly hazard with lambda = -ln(1 - p) per year, so the chance of at least one release in a year equals p. Source unit type is drawn from the “where from” flag counts below; release type flags (gas, liquid, fire, explosion, runaway) are drawn independently with probability flag count / 2,611. The filing stream draws one Bernoulli per simulated year with the implausible-filing share, and raises an alert on the control building.

Alerts. A release applies a short model signature to its source unit (gas reading up, pressure or level down). An alert is raised when a model limit is first crossed. Normal noise is bounded and never reaches a limit; a test in the repository checks this. Because the drawn rates are low, many seeds show no release inside the horizon. That is the honest behaviour of the statistic, not a defect: use Next incident, another seed, or Inject test excursion.

Ontology pattern. Objects (Unit, Alert, Incident, WorkOrder, Filing), links between them, and action types with parameters and submission criteria follow the pattern in ehs-osha-analysis src/ehs_osha/ontology/spec.json. The filing action is that repository's “Flag filing as implausible”. Every action, applied or rejected, writes an audit entry with who, what and when (simulated time). The log exports as JSON and includes the seed, parameters, rates and ontology so a run can be reproduced. Independent design on public data; not affiliated with Palantir.

Limits. The simulation says nothing about the risk of a real plant or any real layout. A plant-level rate is applied to one synthetic site, so unit-level incident rates are not estimated. Release flags describe where a release came from, not why. Time runs for up to 100 simulated years so that low-rate events can appear, which also means the site does not age, change or learn. The 3D model, dimensions (in drawing units) and unit counts are illustrative. Fire, explosion and runaway flags are recorded and drawn only as part of the incident record. The insight panels cite the exact file and key for every figure and make no causal claim.
